# VR menu text and Follow controls correction — 2026-11-09

Pointing now changes the hand and wrist only. It no longer forces elbow extension or neutral arm twist: those joints retain normal tracked motion. The normal Follow elbow mapping still includes the mechanical straight offset, so full extension remains available without using a pointing gesture. Wrist-pitch/roll alignment and the straight upper pointing finger remain.

Right A restores the regular task menu, including Follow / Record, recording and overdub, even if the temporary Selections page was previously opened or closed. Right B retains menu Back and Follow Stop behavior. Left A remains the mirror toggle; Left B alone opens/closes Selections. Split stick locomotion and the left-stick-click laser raise/lower toggle remain unchanged.

A fresh left-trigger pull fires the visible laser when it has reached its lowered position (within a small endpoint tolerance). Firing is suppressed while menus are open, while the laser is raised or still lowering, or when a raise target is active. Holding the trigger does not repeatedly restart the effect. Both source-restricted SteamVR input and the direct fallback expose a separate left-trigger state; a right trigger or A/B button is not substituted. The editor rechecks visibility and lowered position before firing. This uses the existing laser animation and sound preview, including during Follow overdub playback; it does not insert a Fire Laser timeline command into a recorded body take.

VR raster font audit: the main menu and the editor-panel frame were the remaining production drawing paths using point-sized fonts in fixed pixel boxes. Both now use explicit GraphicsUnit.Pixel fonts. Menu titles and instructions fit their safe areas; eight shorter rows leave more room for help text. Row hit testing matches the new spacing. Editor-frame title, toolbar buttons and footer help also fit their available boxes. Pose labels/dial, glove LCDs, transport panel, Follow status and calibration graphics already used pixel-sized fonts. Normal Windows/WPF desktop UI fonts are not converted, since their layout uses desktop scaling rather than these fixed bitmap boxes.

Validation: 52 focused checks passed, covering existing split routing, normal elbow extension, pointing without elbow/twist overrides, trigger source precedence and laser gating, right-A recovery of the regular menu from visible/closed Selections, right-B Back, menu-row hit testing and full title/help fit at 96/144/192 DPI. Actual menu previews were rendered and inspected. Release publish completed for both VR applications. No full test suite or headset integration test was run, as requested.

Install: close VR Player and VR Editor and extract J5Studio-VR-Menu-Text-And-Follow-Controls-update.zip over the existing portable VR folder, keeping its subfolders. This package is cumulative since Johnny5VR-0.9.0-cumulative-update-2026-11-08.zip and includes the previous startup readiness, calibration alignment and split-stick changes. Config, Settings, models and saved calibration are not overwritten. The regular Desktop application is not deployed.
