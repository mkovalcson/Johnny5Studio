# Fall Apart — 1.37.1

Added a **Fall Apart** timeline command that replays a baked rigid-body collapse of the full-body URDF. Forwards the robot shudders for 0.5 s and every body part falls to the floor as a separate piece, with the head from the LED mouth up as one piece; reversed, the pieces reassemble and servo control resumes. The clip (`FullBodyModel/Meshes/Body/FallApart/fall_apart.json`, 105 frames at 30 fps, 701 links) is baked by `FullBodyModel/Body/bake_fall_apart.py` with PyBullet. See `FullBodyModel/Body/REQ-fall-apart.md` for the bake, the format and the display design.

The command is a URDF-only text command, `{"reverse":false,"speed":1}`, available in Edit Commands (with a Build… direction prompt) and through the new `insert_fall_apart` API method, which returns `endSeconds`. `get_state.urdf.fallApart` reports whether the loaded model has a clip. The latest command at or before the cursor determines the frame, so seeking is exact. While active, every joint node shows an override matrix instead of joint motion; the originals keep tracking the joints, and restoring them releases the effect exactly. Parts blend from the live pose during the shudder. Collision warnings are suppressed in pieces; hardware output and hardware exports ignore the command; Headroom re-timing moves it with other commands.

Built on the live 1.37.0 source (hand-closing limits and backdrop-only models included). The clip was re-baked against that model: poses are bit-identical to the 1.36.5-model bake, because link names and zero-pose geometry did not change.

Validation: Release build 1.37.1 succeeded with the existing two CS0649 vent-center warnings. `--fall-apart` passed 80 assertions, including frame 0 matching the model's zero pose for every link, every link reaching its baked final pose within 1 µm, joint motion ignored while in pieces, and exact restoration after release. General regression (6,596), recent features (466), new-feature UI (86) and body/audio (139) passed. `--editor-api`, `--urdf-model`, `--urdf-presentation` and `--controllers` stop at their first assertion on this machine; the 1.37.0 source without this change fails at the same four assertions, so these are pre-existing and their remaining assertions did not run (including the existing API insertion checks). No physical robot was driven.
