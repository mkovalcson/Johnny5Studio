# Video Clips — 2.4

Added **Video Clip**, a URDF-only text command (`ServoNames.VideoClip`, appended to the enum) that shows a video behind the robot for its span on the timeline. Settings JSON: `{"path":"VideoMedia/take-<guid>.mp4","fit":"Contain","volume":100,"muted":false,"skipSeconds":0,"endSeconds":null,"sourceSeconds":12.5}`. `sourceSeconds` is the file's length, read at import by Media Foundation (`MF_PD_DURATION`; works without a sound track), so a clip keeps its span when the file is missing. Played span = `(endSeconds ?? sourceSeconds) − skipSeconds`.

## Timeline

- Like `Play`, it has no servo-grid row. Each clip is a violet bar in a 24 px strip above the time axis (bottom of the Scene section in the three-lane layout), with its file name and a 1 ms envelope of its sound from `MediaAssetCache` (dimmed when muted; red when the file is missing; "(no sound)" when decoding fails, remembered per path).
- Bar drag moves only that clip (no ripple) and is clamped between its neighbours in the view; release commits one undo step. Plain click moves the cursor; double-click opens settings; right-click: settings, move cursor to start, delete.
- Insert from the timeline context menu: length probed first (so a refused clip is never copied), overlap checked, then copied into `Config/VideoMedia`. A file with the same stem, size and modified time already there is reused.
- Settings (CommandSettingsWindow): Fit, Volume, Muted, Skip to, End at (empty = end of file); refused when the new span would overlap.
- No overlaps: insert/move/settings refuse them. `RefreshAfterEdit` calls `GuardVideoClipOverlap`: any other edit that introduces an overlap (marker drags, Edit Commands, paste, audio-handle ripple) is undone with a message when the pre-edit snapshot was clean; undo/redo and loaded files only get a status warning (the later clip wins, like audio clips).
- Excluded from Library Sequence saves, headroom retiming tracks, collision evaluation, hardware dispatch and exports (all via `IsUrdfOnly` plus explicit filters). Edit Commands lists it as a text row and validates its JSON on close.

## Playback

- View: a muted `MediaElement` inserted behind `_viewport` (above the backdrop brush, so Contain bars show the backdrop colour). Follows the transport like TV Show: plays at the editor rate, re-seeks on drift over 0.15 s, seeks while paused/scrubbing. Hidden views do not decode. While a clip is active the 3D stage model is detached (`_videoHidesStage`, also honoured by `ConfigureStage`) and re-attached after; stage motion keeps updating. TV commands evaluate as inactive during a clip.
- Sound: `VideoClipAudio` — its own `WaveOutEvent` + `AudioFileReader` (Media Foundation), fresh reader/device per start, frame-aligned seek, `LimitedAudioSamples` at End at, `RateSampleProvider` for Playback Speed, volume = Playback Volume × clip volume. Re-seeks on drift over 0.12 s; stays silent once a shorter sound track runs out; gives up on a file after 3 failed opens per run. Silent while paused/scrubbing.
- The mouth reads only `_activeSource` (voice audio), so video sound never drives it. With no voice playing, the video device position feeds `PlaybackClock` as the output time.
- Content end and the Play button's "has audio" test include video clips.

## Editor API and MCP: seeing the video

Read-only methods so an AI can choreograph to a clip: `get_video_clips` (also `get_state.videoClips`), `get_video_frames` (`times` up to 12, or `startSeconds`/`endSeconds`/`interval`; `maxWidth` 480) and `get_view_snapshot` (`maxWidth` 800). Pictures come from `VideoFrames`: a Media Foundation source reader with video processing to RGB32 (top-down rows, negative strides flipped, the unused fourth byte set opaque), reading forward up to 1.5 s instead of seeking, and reopening and reading forward when a file refuses to seek (seen with Media Foundation's own sink-writer MP4s; possibly fragmented recordings). Times past the end give the last picture. Decoding runs on a worker while the UI thread waits. The snapshot is composed in `RobotHeadView.RenderSnapshot`: backdrop brush, the decoded picture with the clip's fit, then a RenderTargetBitmap of the 3D viewport (MediaElement frames never reach RenderTargetBitmap). Images are JPEG data URLs.

MCP server (`Johnny5-Editor-MCP` in the workspace root, backup in `backup-before-video-tools-20261022`): new tools `list_video_clips`, `get_video_frames` (caption + image per frame) and `get_view_snapshot`, choreography guidance in the server instructions, `videoClips` in the get_state summary, and pipe replies read in 64 KiB blocks instead of one byte at a time. Image tools are annotated `Image | dict` / `list[str | Image] | dict`: with MCP SDK 2.2 a bare `Any` return made the SDK serialize the result as structured output and fail, which had also broken the existing `get_library_thumbnail`.

Validation (build 2.4.5): Release build succeeded. `--video-clips` passed 41 assertions: settings parsing/validation/round-trip, URDF-only/text/lane/no-disable rules, save/load, timeline evaluation, overlap detection and insert/move blocking, a real Media Foundation MP4 (length probe, sound decode, import into VideoMedia and reuse), the timeline bar rendered in an off-screen window (colour and hit-testing in the strip only), drag clamping between neighbours, and a shown view hiding the 3D stage during a clip, keeping it hidden across a backdrop change and restoring it after. `--video-clip-preview <video> <png>` rendered the head over a playing sample video with the green backdrop in the Contain bars. `--tv` (43) and `--help` (111) passed. ## Robot Frames export (File > Export Robot Frames)

A transparent PNG sequence of the robot at exact timeline times, for compositing over the original video. Settings (`RobotFrameExportSettings`: size 1920 × 1080, 30 fps, 0 s to end of sequence via `EndSeconds = null`, folder default "<sequence> frames", robot only, match video) are remembered per sequence (key relative to Configuration) in `Config/RobotFrameExports.json`. The dialog measures the average PNG size and capture time from frames rendered at the start, middle and end.

Rendering: RenderTargetBitmap of the Viewport3D was abandoned: WPF renders 3D into bitmaps in software, about 10.5 s a frame regardless of resolution for the 1.1M-triangle full body. Instead a dedicated export `RobotHeadView` (configured like the undocked view, joined to `ForEachHeadView` only while `_exportingFrames`) is drawn by WPF on the GPU in a borderless window and read with `PrintWindow(PW_CLIENTONLY | PW_RENDERFULLCONTENT)`. Findings: Windows does not refresh the parts of a window that are off screen (fully off-screen windows never update; partly off-screen ones update only the visible part reliably), but a covered window updates fine. So the window sits behind the editor, scaled to the on-screen view's shape so the framed area is exactly the output size, and placed so that area is on the primary screen from (0, 0); the area must fit the screen. Captures lag 2–6 renders, so two markers at opposite corners of the area take a new, widely different colour per capture and a capture counts only when both show it. Each frame is captured over black and white backgrounds; alpha = 255 − max channel difference, colour = the over-black capture (premultiplied), exact for WPF's blending, with hardware antialiasing. The area is copied centred into the output. Calibrated servo motion is paused and stepped by exactly 1/fps per frame (first frame snapped); the mouth follows `DesiredSourceAt` amplitudes; video clips are hidden (stage hiding kept); robot-only removes the 3D stage from the export view only.

Validation: `--robot-frames` 29 assertions (settings, frame maths, per-sequence store, framing areas, crop placement, a 1920 × 1080 GPU capture with a transparent background, opaque premultiplied robot and soft edges, repeatability, stage hiding/restoring). Measured on this PC (GTX 1080 Ti): 234 ms per 1080p frame, 234 KB. `--video-clips` 65, `--editor-api` 90, `--tv` 43, `--help` 111, general 6,699, recent features 470, URDF presentation 253, scene setup 151, meeting 18 pass. Not exercised: the dialog and a full export in the running editor.
